# 智慧集市系统设计摘要

## 角色与边界

系统包含普通用户、小贩、集市管理员、超级管理员四类身份。公开注册只能创建普通用户或小贩；集市管理员由超级管理员创建。Spring Security 负责 URL 级授权，Service 层继续校验订单、摊位和集市的数据归属。

## 最小业务闭环

```text
小贩注册 → 申请空闲摊位 → 集市管理员审批
    → 小贩维护商品并上架
    → 用户浏览商品 → 加入购物车 → 创建订单 → 模拟付款
    → 小贩备货完成 → 订单待取货 → 用户确认取货
    → 订单完成 → 小贩/管理员收入统计
```

订单状态只允许按 `待付款 → 已付款 → 待取货 → 已完成` 前进。待付款订单可取消并恢复库存；支付后不提供直接取消，避免当前未接入退款系统时出现账实不一致。超过 30 分钟仍待付款的订单由定时任务取消。

## AI 客服与离线兜底

`AiChatService` 协调三类答案来源：实时在售商品目录、`src/main/resources/ai/faq.json` 本地知识库、外部兼容 Chat Completions 的模型。商品问题优先查询数据库；已命中的平台规则由知识库直接回答；只有未命中知识库但仍属于集市经营范围的问题才调用主、备模型。无关问题不调用模型，也不进入会话历史。

文案类请求使用独立约束：模型只能使用用户明确提供的事实，并采用条件式或愿景式表达。服务端会检查未经验证的质量、库存、优惠、营业及现场描述，必要时要求模型安全重写；仍不合格则返回 `unknown`。系统不编造个人订单、审批、支付或实时经营状态。

通用模型回答还会检查敏感信息索取、个人状态猜测、代执行声明、虚构链接和指令覆盖内容。完整白名单、事实来源和维护规则见 `docs/AI_RESPONSE_RULES.md`。

外部模型密钥只保存在后端私有配置或进程环境中。主模型失败时可使用被 Git 忽略的备用配置；相关持久化方式见 `docs/AI_BACKUP_CONFIG.md`。

## 通知与数据

业务通知先写入 `notification` 表，再通过 WebSocket 推送刷新信号；WebSocket 不可用时前端使用带 Bearer Token 的 SSE 接口降级。两种实时通道都不直接携带敏感业务数据。

数据库基线位于 `database/schema.sql`，演示商品位于 `database/seed_market_atmosphere_products.sql`。静态演示商品照片放在 `src/main/resources/static/products`，默认头像位于 `src/main/resources/static/images/default-avatar.svg`。
